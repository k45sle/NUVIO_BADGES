## 🟡 Performance

- **No gzip/brotli in `default.conf`.** The stock `nginx.conf` ships with `gzip` commented out, and you only mounted `conf.d/default.conf`, not the main config — so it's off. `index.html` (~23KB) and `app.js` (~25KB) are served raw. Cloudflare's edge likely compresses this for public visitors anyway, but the tunnel leg to origin and any direct/local access (like your `curl localhost:8090` checks) get it uncompressed. Free, zero-risk fix.
- **No `Cache-Control` headers anywhere** — and this is worth connecting directly to the bug you spent this whole session on. With no origin `Cache-Control`, Cloudflare falls back to its own default heuristic caching for static extensions, which is exactly what served that stale `app.js` (`cf-cache-status: HIT`) before your fix. Setting explicit headers at the nginx layer — long/`immutable` for the versioned JS, `no-cache` for `index.html`/`manifest.json`/`service-worker.js` — gives you a durable fix instead of relying purely on remembering to bump `?v=` (your own TODO #2/#3 flagged this as manual/fragile).
- **Zero timeouts anywhere.** Every `fetch()` (weather, holidays, news, reddit, health checks) and the `getCurrentPosition()` call has no timeout/`AbortController`. A stalled API or a GPS lock that never resolves leaves a permanent "Loading..." with no fallback — same root cause as the health-check issue above, just a different symptom.
- **`api.rss2json.com` is called fresh on every load and every tab switch, for both News and Reddit, with no client-side caching.** That's a well-known low-quota free proxy; two widgets hammering it with zero caching is a real rate-limit risk plus needless latency. A few minutes of `sessionStorage` caching would cut this a lot.
- **Weather polls every 120s even when the tab is backgrounded** — no Page Visibility check to pause it.
- **Preconnects exist only for Google Fonts** — none for `api.open-meteo.com`, `api.rss2json.com`, `date.nager.at`, or `i.postimg.cc`, all of which are hit on first paint.
- **The brand logo is hotlinked from `i.postimg.cc`** — cross-origin, so the service worker's own-origin check (`url.origin !== self.location.origin`) skips it entirely. It's the one image always visible on every load, and it's the one image with no offline/cache story and an external SPOF.

## 🟢 Technique upgrades

- **Race conditions on rapid tab/mode switching.** `loadNews`, `loadReddit`, and `fetchWeather` have no request-cancellation or sequence guard. Fast double-clicking between US/World or funnycats/funny can let an older, slower response land after a newer one and overwrite what's currently marked active. An `AbortController` per switch (or a simple incrementing token check before render) fixes this cleanly.
- **Proxy the three health checks through the dashboard's own nginx** (`location /healthproxy/rstream { proxy_pass https://rstream.237119.xyz/api/v1/health; }`, etc.). That turns them same-origin, lets you drop `no-cors` for a real readable status code (actually fixing bug #2), lets you attach a timeout, and lets you remove three origins from `connect-src` in the CSP.
- **Security header pass, matching the rigor you already put into CSP:** `server_tokens off;` (nginx version disclosure), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, and `X-Frame-Options: SAMEORIGIN` as defense-in-depth alongside `frame-ancestors 'self'`.
- **Small UX/accessibility batch:** no way to close the search box once opened (no Escape handler, no ✕) — you can only exit by clicking outside with an empty field; no `placeholder`/`aria-label` on the search input; the header-click-to-search interaction has no keyboard path; the news/reddit/weather tab buttons don't expose `role="tab"`/`aria-selected`; calendar prev/next buttons have no `aria-label`; the search `<form target="_blank">` is missing `rel="noopener"`.
